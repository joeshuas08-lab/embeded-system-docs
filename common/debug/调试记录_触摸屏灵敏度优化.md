# ILI211X 触摸屏驱动移植

## 问题现象

- 触摸无反应
- 触摸点坐标偏移
- 多点触摸乱报

## 排查路径

```
触摸无反应
→ getevent -l 看有没有 input event
→ 没有 → 查中断触发了吗？cat /proc/interrupts | grep touch
→ 中断也没 → 查 I2C 通信正常吗？i2cdetect -y <bus>

坐标偏移
→ 查驱动中 flip/swap X-Y 配置
→ 查 touch 面板安装角度

多点乱报
→ 查 ABS_MT_TRACKING_ID 是否正确分配和释放
→ 查 BTN_TOUCH 是否同步
```

## 根因分析

### 驱动移植要点

ILI211X 驱动的核心工作：

```
I2C 读触控点数据 → input_report_abs(ABS_MT_POSITION_X/Y)
                  → input_report_key(BTN_TOUCH, 1)
                  → input_sync()
```

移植时确保：
1. **I2C address** 和硬件原理图一致（ILI211X 常见 0x41 或 0x42）
2. **中断 GPIO** 触发沿正确（通常下降沿）
3. **坐标翻转**：sensor 安装方向和 LCD 方向不同时需要软件翻转 X/Y

### 灵敏度调节

不影响硬件的情况下，软件可以调节的参数有限：
- **采样率**：设备树中 `touchscreen-poll-interval`（默认一般不需要改）
- **上报阈值**：驱动中 `touch_pressure` 或 `touch_size` 参数
- **去抖**：Linux input core 的 `debounce` timer（一般不配）

大多数"灵敏度"问题其实是硬件 noise 导致误触发，不是软件参数能解决的。

## 验证清单

```bash
# 0. I2C 通信
i2cdetect -y <bus> | grep 41      # ILI211X 在？

# 1. 输入设备注册
cat /proc/bus/input/devices | grep -A 10 ILI

# 2. 原始事件
getevent -l /dev/input/eventX     # 触摸时有事件？

# 3. 坐标验证
# 画对角线，检查 X/Y 是否线性
```

## 典型失败模式

| 症状 | 最可能原因 | 第一检查点 |
|------|-----------|-----------|
| getevent 无输出 | 中断未触发 / I2C 不通 | cat /proc/interrupts |
| 触摸点镜像 | X/Y 未 swap | 驱动中修改 SWAP_XY |
| 坐标反向 | flip 配置反了 | 查驱动的 invert_x/y 配置 |
| 同时触摸多个点乱报 | TRACKING_ID 管理有 bug | 查 slot 释放逻辑 |
| 偶尔无响应 | 中断被其他设备共享 | cat /proc/interrupts 查 irq 号 |
