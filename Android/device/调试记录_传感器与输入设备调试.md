# 高级工程师调试记录：传感器与输入设备调试

## 功能概述
传感器和输入设备是嵌入式系统与物理世界交互的关键接口。在 RK3576 Android 14 平台中，涉及 ICM42607 陀螺仪方向修正、触摸屏 90° 旋转适配和用户自定义按键配置。调试需要结合设备树配置、驱动参数调整和系统层适配，确保传感器数据正确、输入响应准确。

## 常见问题及解决方案

### 1. 陀螺仪方向错误（commit `cb5bded24247`, `9b75f73c2afd`）
**问题：** ICM42607 陀螺仪在设备上的安装方向与默认坐标系不匹配，导致读数方向错误。

**解决方案：**
在设备树中配置陀螺仪方向矩阵：

```dts
// myd-lr3576.dts
&i2c2 {
    icm42607: icm42607@68 {
        compatible = "icm42607";
        reg = <0x68>;
        interrupt-parent = <&gpio3>;
        interrupts = <RK_PB3 IRQ_TYPE_LEVEL_LOW>;
        
        // 修正安装方向 - mount matrix
        mount-matrix = <
            -1 0 0   // X 轴翻转
            0 -1 0   // Y 轴翻转
            0 0 1    // Z 轴不变
        >;
    };
};
```

**方向矩阵说明：**
- `mount-matrix` 是一个 3×3 旋转矩阵
- 每个轴的值范围为 [-1, 1]
- 负数表示该轴方向翻转
- 可通过实验确定正确的矩阵值

**验证方法：**
```bash
# 安装传感器测试工具
adb shell dumpsys sensorservice | grep -A 20 "ICM42607"

# 旋转设备检查各轴数据方向
# 将设备平放，依次绕 X、Y、Z 轴旋转
# 确认读数方向与预期一致

# 使用命令行查看原始数据
watch -n 1 'adb shell dumpsys sensorservice 1 2>/dev/null | head -5'
```

### 2. 触摸屏旋转 90°（commit `b358c6d6c1cc`）
**问题：** 触摸屏的物理安装方向与显示屏方向相差 90°，需要软件旋转触控坐标。

**解决方案：**
在触摸屏驱动中旋转坐标：

```c
// kernel-6.1/drivers/input/touchscreen/gt1x/gt1x_generic.h
// 修改坐标映射，将触摸坐标旋转 90°

// 旋转前：
// x_raw → x_axis
// y_raw → y_axis

// 旋转 90° 后：
// x_raw → y_axis  
// y_raw → MAX_X - x_axis

#define SWAP_XY 1
#define INVERT_X 1
#define INVERT_Y 0
```

或者通过输入子系统坐标转换：
```c
static void gt1x_rotate_coords(struct gt1x_device *dev, int *x, int *y)
{
    int tmp = *x;
    *x = *y;
    *y = dev->max_x - tmp;
}
```

**验证方法：**
```bash
# 使用 getevent 检查触摸坐标
getevent -l /dev/input/eventX

# 绘制对角线，验证触摸轨迹与显示一致
adb shell input swipe 0 0 799 479 1000
```

### 3. 用户按键配置（commit `ab0de5b32a3f`）
**问题：** 需要添加或自定义用户按键（如音量、功能键等）的 GPIO 映射。

**解决方案：**
在设备树中配置 GPIO 按键：

```dts
// myd-lr3576.dtsi
/ {
    gpio-keys {
        compatible = "gpio-keys";
        pinctrl-names = "default";
        pinctrl-0 = <&key_vol_up>;
        
        volume-up {
            label = "Volume Up";
            linux,code = <KEY_VOLUMEUP>;
            gpios = <&gpio1 RK_PC5 GPIO_ACTIVE_LOW>;
            debounce-interval = <10>;
        };
        
        volume-down {
            label = "Volume Down";
            linux,code = <KEY_VOLUMEDOWN>;
            gpios = <&gpio1 RK_PC6 GPIO_ACTIVE_LOW>;
            debounce-interval = <10>;
        };
        
        // 自定义功能键
        custom-key {
            label = "Custom Key";
            linux,code = <KEY_F1>;
            gpios = <&gpio1 RK_PC7 GPIO_ACTIVE_LOW>;
            debounce-interval = <10>;
        };
    };
};
```

**pinctrl 配置：**
```dts
&pinctrl {
    keys {
        key_vol_up: key-vol-up {
            rockchip,pins =
                <1 RK_PC5 RK_FUNC_GPIO &pcfg_pull_up>;
        };
        key_vol_down: key-vol-down {
            rockchip,pins =
                <1 RK_PC6 RK_FUNC_GPIO &pcfg_pull_up>;
        };
        key_custom: key-custom {
            rockchip,pins =
                <1 RK_PC7 RK_FUNC_GPIO &pcfg_pull_up>;
        };
    };
};
```

**验证方法：**
```bash
# 查看按键设备
cat /proc/bus/input/devices | grep -A 5 "gpio-keys"

# 监听按键事件
getevent -l /dev/input/eventX

# 测试按键上报
adb shell input keyevent KEYCODE_VOLUME_UP
```

## 调试案例

### 案例一：ICM42607 陀螺仪方向修正（commit `cb5bded24247`）
**背景：** 陀螺仪数据方向与设备坐标系不一致，导致应用层获取的姿态信息错误。

**调试过程：**
1. 读取原始陀螺仪数据，确认各轴方向
2. 计算正确的 mount-matrix 参数
3. 在设备树中配置方向矩阵
4. 使用传感器测试工具验证各轴数据

**经验总结：**
- 陀螺仪方向修正优先使用 mount-matrix 设备树属性
- 避免在驱动层硬编码坐标转换，便于后续调整
- 验证时需测试所有 6 个方向（±X、±Y、±Z）

### 案例二：触摸屏坐标旋转适配（commit `b358c6d6c1cc`）
**背景：** 触摸屏物理安装旋转 90°，触摸坐标与显示内容不匹配。

**解决方案：**
在 gt1x 驱动中修改坐标映射逻辑，交换 X/Y 轴并翻转 X 轴。

**验证：**
- 触摸屏幕四个角落确认坐标正确映射
- 绘制直线和圆弧验证触摸轨迹的准确性

## 注意事项
1. **传感器校准**：更换陀螺仪后需重新校准，确保数据准确性。
2. **坐标旋转一致性**：触摸屏坐标旋转需与显示方向保持一致，避免操作错位。
3. **按键防抖**：GPIO 按键需设置合适的防抖时间（通常 10-50ms），避免误触发。
4. **输入设备优先级**：多个输入设备时需注意事件分发优先级。
5. **坐标系一致性**：确保应用层和驱动层的坐标系定义一致。
