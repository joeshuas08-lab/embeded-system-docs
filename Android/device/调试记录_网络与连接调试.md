# 高级工程师调试记录：网络与连接调试

## 功能概述
网络和连接功能是 Android 设备的基础服务，涉及 WLAN 热点、蓝牙和 NTP 时间同步。在 RK3576 Android 14 平台中，这些功能的调试包括 WLAN 热点 IP 地址配置、蓝牙权限兼容性修复以及 NTP 服务器地址配置。本记录总结这些网络与连接相关问题的调试经验。

## 调试方法

### 1. WLAN 热点调试
```bash
# 查看热点状态
adb shell dumpsys wifi | grep -i hotspot

# 查看热点配置
adb shell dumpsys wifi | grep -A 20 "Soft AP"

# 查看 DHCP 服务器状态
adb shell dumpsys netd | grep -i dhcp
```

### 2. 蓝牙调试
```bash
# 查看蓝牙服务状态
adb shell dumpsys bluetooth_manager

# 查看蓝牙权限相关日志
adb logcat -s BluetoothPermissionRequest

# 查看蓝牙配对信息
adb shell dumpsys bluetooth_manager | grep -i bond
```

### 3. NTP 时间同步调试
```bash
# 查看当前 NTP 配置
adb shell getprop persist.sys.ntp_server
adb shell getprop ro.com.google.time.noserver

# 查看时间同步日志
adb logcat -s TimeSynchronizer

# 手动触发 NTP 同步
adb shell settings put global auto_time 0
adb shell settings put global auto_time 1
```

## 常见问题及解决方案

### 1. WLAN 热点 IP 地址冲突（commit `3c594afc077`）
**问题：** 默认热点 IP 地址段与客户网络环境冲突，导致客户端无法连接。

**解决方案：**
在 `config.xml` 和 `PrivateAddressCoordinator.java` 中修改热点 IP 地址段：

```xml
<!-- frameworks/base/core/res/res/values/config.xml -->
<!-- 配置热点 IP 地址范围 -->
<string-array name="config_tether_wifi_regexs">
    <item>"192.168.43.1"</item>  <!-- 热点网关 IP -->
</string-array>
<string-array name="config_tether_dhcp_range">
    <item>"192.168.43.2"</item>   <!-- DHCP 起始 -->
    <item>"192.168.43.254"</item> <!-- DHCP 结束 -->
</string-array>
```

**修改要点：**
```java
// frameworks/base/core/java/android/net/tethering/PrivateAddressCoordinator.java
// 调整私有地址分配逻辑，确保热点 IP 固定为 192.168.43.1
private static final String HOTSPOT_IP = "192.168.43.1";
```

**验证方法：**
```bash
# 开启热点
adb shell svc wifi set hotspot enabled true

# 连接后查看客户端的网关地址
# 应在 192.168.43.1 网段
```

### 2. 蓝牙权限请求异常（commit `ea4ec01cd49`）
**问题：** 应用请求蓝牙权限时，`RequestPermissionActivity` 显示异常或崩溃。

**调试步骤：**
1. **检查权限请求流程**：
   ```bash
   adb logcat -s BluetoothPermissionRequest -v time
   ```

2. **修复方案**：修正 `RequestPermissionActivity.java` 中的 UI 逻辑和权限处理流程

3. **验证修复**：
   ```bash
   # 模拟三方应用请求蓝牙权限
   adb shell am start -a android.bluetooth.adapter.action.REQUEST_ENABLE
   # 确认权限对话框正常显示和处理
   ```

**关键修改（`packages/apps/bluetooth`）：**
```java
// RequestPermissionActivity.java 修复
// - 修正对话框取消后的回退逻辑
// - 修复权限回调处理
// - 优化 UI 状态管理
```

### 3. NTP 服务器无法连接（commit `c18c1fd095c`）
**问题：** 默认 NTP 服务器在国内网络环境下无法连接，导致系统时间无法同步。

**解决方案：**
更换为可用的 NTP 服务器：

```xml
<!-- device/rockchip/rk3576/overlay/frameworks/base/core/res/res/values/config.xml -->
<string name="config_ntpServer" translatable="false">ntp.aliyun.com</string>
<!-- 或 -->
<string name="config_ntpServer" translatable="false">cn.pool.ntp.org</string>
```

**设备级配置（`rk3576_u.mk`）：**
```makefile
# 预置 NTP 服务器
PRODUCT_PROPERTY_OVERRIDES += \
    persist.sys.ntp.server=ntp.aliyun.com
```

**验证方法：**
```bash
# 确认 NTP 服务器地址
adb shell getprop persist.sys.ntp.server

# 手动测试 NTP 连通性
adb shell ping ntp.aliyun.com

# 查看时间同步结果
adb shell date
```

**背景：** 客户需求将热点 IP 固定为 192.168.43.1，与 DHCP 分配的地址段一致。

**验证方法：**
```bash

# 触发蓝牙权限请求
# 确认对话框正常显示
```

### 案例三：NTP 服务器替换（commit `c18c1fd095c`）
**背景：** 默认 NTP 服务器（通常是 google 的 NTP）在国内网络无法访问，导致系统时间不同步。

3. 在 overlay 和系统属性中配置新的 NTP 服务器

## 注意事项
1. **IP 地址规划**：热点 IP 地址段应避免与常见局域网段（如 192.168.1.x）冲突。
2. **蓝牙兼容性**：不同 Android 版本对蓝牙权限的处理方式不同，需注意 API 差异。
3. **NTP 选择**：选择稳定可靠且延迟低的 NTP 服务器，国内建议使用 `ntp.aliyun.com` 或 `cn.pool.ntp.org`。
4. **权限审计**：涉及蓝牙权限的修改需通过权限合规审计。
5. **多网络适配**：调试时需考虑用户在不同网络环境（家庭、企业、移动网络）下的使用场景。
