## 一、当前已实现能力（现状基线）

1. 前端（`public/index.html`）
   - 蓝白风格问答 UI
   - 通过 `fetch('/api/chat')` + SSE 接收流式输出
   - 逐段渲染回复文本

2. 后端（`server.js`）
   - Express 提供静态页面与 `/api/chat`
   - 通过 `openclaw agent --json` 调用模型
   - 兼容多种 JSON 结构提取（`result.payloads[0].text` / `reply` / `choices...`）
   - 防止提示词回显（过滤 skill/system prompt 泄露）
   - 本地知识检索（`memory/*.md` + `skills/**/references/*.md`）
   - 若模型未返回 `Sources`，后端自动注入命中文档路径

3. Skill（`skills/dev-center-assistant/SKILL.md`）
   - 已提升为工程师风格（结论先行、证据导向、可执行建议）
   - 去掉邮件特性，保留专业知识组织逻辑

## 二、这套系统为什么会慢（根因）

### 关键瓶颈
- 每次请求都要启动一次 `openclaw agent` 子进程
- 启动 + 会话恢复 + 模型推理 是主要耗时

### 非主要瓶颈
- 前端渲染和 SSE 发送只占很小比例

## 三、已踩坑与修复记录

1. **JSON 解析失败 / 前端显示“未找到内容字段”**
   - 原因：CLI 输出夹杂日志，且字段结构变化
   - 修复：截取最外层 JSON + 多路径字段提取

2. **提示词泄露到前端**
   - 原因：回退到了 `message/text` 字段（可能是请求内容）
   - 修复：仅允许回复字段；增加敏感片段拦截

3. **Sources 一直“无命中”**
   - 原因：检索池被 `.slice(0,300)` 截断
   - 修复：取消截断；增强文件名/路径命中权重

4. **`SIGTERM/SIGKILL` 导致命令失败**
   - 原因：请求超时或进程被系统终止
   - 修复：缩短提示词、降低 thinking、放宽超时

## 八、今天新增优化补充（2026-04-13）

### 1) 强制 Skill 路由 + 专业回复约束
- server 端统一通过 `buildSkillDrivenMessage()` 注入 dev-center-assistant 规则。
- 目标：所有网页侧请求都按同一工程师风格输出。
- 风险点：提示词过长会显著增加 CLI 耗时与失败概率。

### 2) 提示词泄露修复（关键）
- 问题：曾出现提示词原文被回显到前端。
- 根因：解析回退到 `message/text` 字段时，可能把请求体内容当成回复。
- 修复：
  - 只提取模型回复字段（`result.reply / result.payloads / reply / payloads / choices`）
  - 加入敏感片段拦截（命中 `用户问题：` 等即替换为安全提示）

### 3) Sources 机制升级为“检索驱动”
- 旧：仅要求模型输出 Sources（模板层）。
- 新：后端先检索，再把命中资料注入 prompt；若模型未给 Sources，后端强制补充来源路径。
- 实际效果：从“可能无来源”变为“默认有可追溯来源”。

### 4) 检索器覆盖率修复
- 问题：命中率异常低（常出现 `hits=0`）。
- 根因：检索池曾被 `.slice(0,300)` 截断。
- 修复：取消截断，扩大检索集合到全部可用文档。

### 5) 检索精度修复（避免错引）
- 问题：会命中跨平台无关文档（如 J7 问题命中 ST 文档）。
- 根因：仅关键词匹配，缺少型号强约束。
- 修复：
  - 增加厂商 hint（含 `j7/j7a100/tda4`）
  - 提取产品 token（`MYC-* / MYD-* / RKxxxx / Txxxx / J7A100T`）
  - 命中评分中提高“文件名/路径/型号”权重
  - **强门槛**：若问题含具体型号，但候选来源不包含该型号，直接判无命中

### 6) 超时与稳定性优化
- 将 skill prompt 压缩为短指令，减少 token 与启动负担。
- CLI 参数调整为：
  - `--thinking off`
  - `--timeout 90`
  - Node `execAsync` 超时提高至 `120000ms`
- 目的：降低 `SIGTERM/SIGKILL` 概率。

### 7) 与邮件链路的差异复盘（当前认知）
助理链路此前“不准”主要不是文风问题，而是流程缺了三件事：
1. 实体级路由（按平台/型号先分流）
2. 证据质量门槛（弱证据不下结论）
3. 失败降级策略（证据不足时明确待确认项）

目前已补上 1/2 的大部分能力；后续建议继续补齐“查询重写 + 证据门控回答”。

### 8) 当前建议保留的最终组合
1. 短 prompt + 防泄露解析
2. 检索前置 + Sources 后补全
3. 型号强约束过滤
4. 厂商路由优先检索
5. 分段 SSE 输出（保持交互体验）

## 开发者中心Ai FAE Assistant完善总结

更新时间：2026-04-14

### 一、当前已经完善到什么程度

这套问答系统，已经从“简单前端 + 命令转发”升级成了一个带有：

- 技能风格约束
- 本地知识库检索
- 文件级 + 章节级双层索引
- 平台优先路由
- 型号别名归一
- 接口/外设主题优先召回
- 证据等级标注
- Sources 统一格式输出
- 提示词泄露拦截

的技术问答代理。

也就是说，现在它不只是“把问题丢给模型”，而是先做一层检索、筛选、格式化，再把结果交给模型组织答案。

---

### 二、是怎么一步步让它变完善的

### 1. 先把回答风格固定下来

新增：`skills/dev-center-assistant/SKILL.md`

目标：让输出统一成：
- 结论先行
- 结构化
- 工程师口吻
- 专业术语准确
- 参数不确定时写“以实际 BSP/规格书为准”

这一步解决的是“模型回答跑偏、风格不稳、像泛 AI 回复”的问题。

---

### 2. 从“纯模型回答”升级到“检索增强回答”

后端 `server.js` 增加本地知识库检索：
- `memory/*.md`
- `skills/*-docs/references/*.md`
- `skills/soc-platforms/*`

这一步解决的是：
- 回答没有根据
- Sources 长期无命中
- 只能靠模型泛化猜答案

---

### 3. 补上 Sources 强制输出链路

做法：
- 先把命中的资料片段注入 prompt
- 如果模型没有主动输出 `Sources:`
- 后端自动补充命中文件名

后来又做了格式收口：
- Sources 只显示文件名
- 不显示路径
- 不显示 `.md`

这一步解决的是“前端展示太脏、来源不稳定、不可追踪”。

---

### 4. 修复提示词泄露问题

此前出现过：
- skill prompt 被原样回显到前端

修复方式：
- 只提取模型回复字段
- 不再回退读取可能包含请求内容的 message/text 字段
- 对敏感片段（如“用户问题：”）做安全拦截

这一步解决的是“前端把系统提示词显示出来”的严重问题。

---

### 5. 从“全库乱扫”升级到“平台优先路由”

新增：
- `soc-platforms/WIKI.md`
- `soc-platforms/wiki-index-full.json`

当前已形成完整平台知识索引：
- Allwinner
- Rockchip
- NXP
- ST
- Xilinx

检索时先按问题识别平台，再优先查对应平台资料。

这一步解决的是：
- 跨平台误召回
- ST 问题命中 Rockchip 文档
- J7 问题命中无关平台文档

---

### 6. 增加型号 token 和别名归一

例如：
- `st257`
- `ld257`
- `lt257`
- `257`

会互相扩展召回。

还支持：
- `j7a100t -> j7 / tda4 / a100t`

这一步解决的是：
- 文档命名与提问命名不一致
- 明明有资料，但因为型号写法不同而命不中

---

### 7. 从文件级检索升级到章节级检索

新增：
- `soc-platforms/chapter-index-full.json`
- `soc-platforms/scripts/build_indexes.py`

现在不止知道“有什么文件”，还会知道：
- 文件里有哪些章节
- 章节标题是什么
- 对应的摘要片段是什么
- 哪些章节与当前问题最相关

这一步解决的是：
- 只能命中文件，不能命中真正有用的内容块
- 文件太大时答案仍偏泛

---

### 8. 给“文档发现类问题”和“适配类问题”分开处理

不是所有问题都应该一个检索策略。

已经区分：
- 文档发现类问题：
  - “相关文档有哪些”
  - “哪些资料”
  - “manual/guide/pdf”
- 技术适配类问题：
  - “如何适配”
  - “怎么修改设备树”
  - “怎么接屏/接 PHY/接 TP”

这一步解决的是：
- 文档类问题本该返回专题手册，却被 SoC 通用手册压掉
- 适配类问题本该保留接口专题文档，却只返回产品手册
