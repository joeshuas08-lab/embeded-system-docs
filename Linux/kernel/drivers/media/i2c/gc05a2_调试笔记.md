# GC05A2 摄像头驱动调试笔记 (RK3576 + Android 14)

## 概述

GC05A2 是格科微（GalaxyCore）出品的一款 5M Pixel SPI 接口摄像头 sensor，项目基于 RK3576 平台，使用 MIPI CSI-2 接口连接。涉及的主要调试内容包括：sensor 驱动移植、ISP  tuning、帧率控制、镜像/翻转、AF 自动对焦配合。

---

## 一、驱动移植

### 1.1 DTS 配置

sensor 节点定义在 `myz-rk3576-csi0-gc05a2.dtsi`，挂载在 `csi2_dphy0` 下：

```
&csi2_dphy0 {
    status = "okay";
    ports {
        port@0 {
            reg = <0>;
            #address-cells = <1>;
            #size-cells = <0>;
            mipi_in_ucam0: endpoint@1 {
                reg = <1>;
                remote-endpoint = <&gc05a2_out>;
                data-lanes = <1 2>;
            };
        };
    };
};
```

关键配置点：
- **data-lanes = <1 2>**：GC05A2 支持 2-lane MIPI
- **AVDD 供电**：需确保 avdd-supply 在 DTS 正确配置，详见 `[FIX] enabled camera avdd-supply` 提交
- **xvs 同步信号**：部分调试中 xvs 信号异常会导致 ISP 无法锁定帧同步

### 1.2 defconfig

```bash
CONFIG_VIDEO_GC05A2=y
```

已在 `rockchip_defconfig` 使能。

## 二、帧率控制

### 2.1 调试历程

| 提交 | 操作 | 帧率 |
|------|------|------|
| `set cam 30fps` | 设置 30fps | 30fps |
| Revert "set cam 30fps" | 回退 | 25fps |
| `fix camera flip & set frame 25fps` | 最终固定 | 25fps |

### 2.2 帧率配置方法

帧率由 sensor 内部的 VTS（Vertical Timing）和 HTS 寄存器控制：

```
Frame Rate = MCLK / (VTS × HTS)
```

在 gc05a2 驱动中通过 `V4L2_CID_VBLANK` 控制：

```c
// 设置帧率 25fps
struct v4l2_subdev_frame_interval fi = {
    .interval = {
        .numerator = 1,
        .denominator = 25,
    }
};
```

### 2.3 断流问题

> 详细排查方法参考 [CAMERA difficult performace issue——solution & 实操](./CAMERA%20difficult%20performace%20issue——solution%20&%20实操.md)

长时间预览后画面冻结：
- 现象：gst-launch-1.0 预览 10~60min 后画面卡死
- 软重启无法恢复，需硬重启
- DTS 复位引脚配置需与原理图严格一致

最终确认：25fps 在 RK3576 ISP 处理 pipeline 中更稳定，frame interval 余量足够避免 ISP overrun。

## 四、镜像/翻转 (Mirror & Flip)

### 4.1 硬件原理

GC05A2 支持通过寄存器 `0x17` 控制输出方向：

```
Bit[0] - Bit[4]: 保留
Bit[5] - VFLIP:  垂直翻转 (0:正常, 1:翻转)
Bit[6] - VFLIP:  水平镜像 (0:正常, 1:镜像)
```

### 4.2 DTS 配置方式

在 DTS 中通过 `rotation` 属性指定：

```c
rotation = <180>;  // 翻转180度
```

驱动会读取 rotation 并在 stream on 时设置 sensor 寄存器。

### 4.3 调试记录

```
提交历程：
1. add gc05a2 flip        - 初始翻转逻辑
2. fix cam flip           - 修复翻转方向错误
3. [Fix] camera mirro&flip - 镜像与翻转组合场景修正
4. fix camera flip & set frame 25fps - 最终版本
```

**经验**：Mirror/Flip 涉及 sensor 内部设置的坐标系和 ISP 处理的坐标系之间的配合。如果 sensor 端做了翻转，ISP 端不应该再做翻转，否则画面方向会出错。调试时建议打印驱动中实际写入的寄存器值并与 datasheet 对比。

## 五、AVDD 供电问题

### 5.1 `[FIX] enabled camera avdd-supply`

问题：sensor avdd 供电未正确使能，导致 sensor 无法正常工作。

修复方式：在 DTS 中添加 avdd-supply 引用：

```c
avdd-supply = <&vcc_cam_2v8>;
```

并在 regulator 配置中确保：
- regulator-boot-on 正确设置
- 电压值匹配 sensor 要求（GC05A2 典型 AVDD = 2.8V）

### 5.2 调试方法

```bash
# 确认 regulator 状态
cat /sys/kernel/debug/regulator/regulator_summary | grep vcc_cam

# 测量摄像头供电引脚电压
# 如果电压异常，检查 DTS regulator 配置
```

### 6.2 常见问题排查

| 现象 | 检查点 |
|------|--------|
| 无图像 | MIPI 信号、供电、clock、reset 时序 |

| 画面冻结 | ISP 断流、xvs 同步信号 |
| AF 不工作 | VCM 供电、dw9714 驱动、camera3_profiles 配置 |
