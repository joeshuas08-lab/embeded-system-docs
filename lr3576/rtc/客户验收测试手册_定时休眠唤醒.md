**适用固件**：含以下修复的版本
- `550dd5a045c` power: disable AOD and DeviceIdle motion for tablet
- `1a8fba71a21` rtc: hym8563 roll expired alarm to next minute
- `6ea92292fb3` health: stop periodic wakeups（消除未充电 60s 提前唤醒）
- `737a8c44168` rtc: hym8563 alarm 补偿（休眠走快 1.9%，消除按比例提前唤醒）
- Settings/DND 整点唤醒消除（每小时 :00 与 22:00/07:00 的系统定时唤醒已移除）

**交付物**：
- `AlarmTest.apk`（测试工具，可设 alarm + 写 fired.txt 验证派发。2026-09 修复了
  AlarmReceiver 缺 intent-filter 导致 fired.txt 不写的问题，请用新版）
- 本手册

## 一、测试准备（一次性，每台设备）

```sh
adb root

# 1. 禁用日历 provider（提前唤醒源——若固件已默认禁用则跳过）
adb shell pm disable-user --user 0 com.android.providers.calendar

# 2. 关静止节流（DeviceIdle 打断源——若固件已默认 0 则跳过）
adb shell settings put global location_enable_stationary_throttle 0

# 3. 安装测试工具
adb install AlarmTest.apk

# 4. 防息屏干扰（测试期间）
adb shell svc power stayon true
adb shell settings put system screen_off_timeout 2147483647
```

**注意**：第 1、2 项最终应由固件固化（我方已在 BSP 文档标注），客户出厂固件若未固化，量产时需工厂脚本执行。

## 二、测试流程

### 测试 A：定时唤醒基本功能（核心）

```sh
# 1. 设 5 分钟定时唤醒（测试工具）
adb shell am broadcast -n com.myir.alarmtest/.AlarmSetReceiver \
  -a com.myir.alarmtest.SET --es delay 300

# 2. 立即下发休眠（模拟产品 app 行为）
adb shell "echo mem > /sys/power/state"

# 3. 观察：设备黑屏深度休眠，约 5-6 分钟后自动唤醒
#    时间特性：绝不提前，最多晚约 1 分钟（RTC 走快补偿的固有设计）
#    期间 USB/ADB 断连属正常（suspend 状态）
```

**验收**：
- ✅ 设备睡 5 分钟以上自动醒（绝不早于设定时间；最多晚 ~1 分钟）
- ✅ 唤醒后 adb 恢复、系统正常、fired.txt 有新行
- ❌ 比设定时间早醒 → 有唤醒源未清，反馈 dmesg（见排查表）
- ❌ 超过设定时间 2 分钟不醒 → 睡死（断电重启并反馈）

### 测试 B：用产品 app 验证（最终验收）

产品 app 按方案实现后（`AlarmManager.setExactAndAllowWhileIdle(RTC_WAKEUP)` + `echo mem`）：
1. 设置产品自己的休眠时长（如 10 分钟）
2. app 下发休眠
3. 验收：按时唤醒 + app 收到回调 + 唤醒后业务正常

### 测试 C：稳定性（连续循环）

```sh
# 重复测试 A，10 轮（或产品验收轮次）
# 每 3 轮重启一次设备
adb reboot   # 重启后重做"测试准备"的 1/2/4 步
```

**验收**：10 轮全部按时唤醒，无一次早醒/睡死。

## 三、常见问题排查

| 现象 | 排查 |
|------|------|
| 比设定时间早醒 | `adb shell "su 0 dmesg \| grep -E 'Resume caused'"`——看唤醒源是什么；`cat /data/data/com.myir.alarmtest/fired.txt`（需 root）判断 alarm 是否真触发（无新增=被别的源唤醒）|
| 超时未醒 | 断电重启，反馈 dmesg（`Resume caused` 无记录 = 芯片 alarm 未触发）|
| mem 失败 | 立即重试 1-2 次（系统有 <2s 近期 alarm 时 mem 被拒属正常）|
| 测试期间时间对不上 | 设备 RTC 时间可能落后真实时间，属预期；**测试期间不要手动改系统时间**（拨时钟会让已设的 RTC_WAKEUP alarm 全部延后）|

- [ ] 测试 A：5 分钟定时唤醒误差 <1 分钟
- [ ] 测试 B：产品 app 定时唤醒回调正常
