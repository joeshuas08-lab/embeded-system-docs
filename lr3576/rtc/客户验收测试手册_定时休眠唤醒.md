## 一、测试准备（每台设备一次）

刷机后 adb 默认关闭，先在设备上开启 USB 调试：设置 → 关于平板电脑 → 连点
"版本号"7 次 → 返回 → 系统 → 开发者选项 → USB 调试。或通过调试串口执行
`settings put global adb_enabled 1`。

```sh
adb root

# 1. 禁用日历 provider（提前唤醒源；若固件已默认禁用则跳过）
adb shell pm disable-user --user 0 com.android.providers.calendar

# 2. 安装测试工具
adb install AlarmTest.apk

# 3. 防息屏干扰（测试期间）
adb shell svc power stayon true
adb shell settings put system screen_off_timeout 2147483647
```

说明：
- 静止节流（`location_enable_stationary_throttle=0`）已由固件固化，无需再设置；
  开机约 10 分钟的 Doze 静止检测唤醒也已随之消除
- 第 1 项（日历 provider 禁用）仍为运行时操作，固件固化待排期

## 二、测试流程

### 测试 A：定时唤醒基本功能（核心）

```sh
# 1. 设 5 分钟定时唤醒（测试工具）
adb shell am broadcast -n com.myir.alarmtest/.AlarmSetReceiver \
  -a com.myir.alarmtest.SET --es delay 300

# 2. 立即下发休眠（模拟产品 app 行为）
adb shell "echo mem > /sys/power/state"

# 3. 观察：设备黑屏深度休眠，约 5-6 分钟后自动唤醒（期间 USB/ADB 断连属正常）
```

验收：
- 通过：睡满设定时长自动醒，且不早于设定时间（最多晚 1 分钟左右，RTC 补偿固有特性）
- 通过：唤醒后 adb 恢复、系统正常、fired.txt 有新行
- 不通过：比设定时间早醒 → 有唤醒源未清，反馈 dmesg（见排查表）
- 不通过：超过设定时间 2 分钟不醒 → 睡死（断电重启并反馈）

### 测试 B：用产品 app 验证（最终验收）

产品 app 按方案实现后（`AlarmManager.setExactAndAllowWhileIdle(RTC_WAKEUP)` + `echo mem`）：
1. 设置产品自己的休眠时长（如 10 分钟）
2. app 下发休眠
3. 验收：按时唤醒、app 收到回调、唤醒后业务正常

### 测试 C：稳定性（连续循环）

```sh
# 重复测试 A，10 轮（或产品验收轮次）
# 每 3 轮重启一次设备
adb reboot   # 重启后重做"测试准备"的 1/3 步
```

验收：10 轮全部按时唤醒，无一次早醒/睡死。

## 三、常见问题排查

| 现象 | 排查 |
|------|------|
| 比设定时间早醒 | `su 0 dmesg \| grep "Resume caused"` 看唤醒源；`cat /data/data/com.myir.alarmtest/fired.txt`（需 root）判断 alarm 是否真触发（无新增 = 被别的源唤醒）|
| 超时未醒 | 断电重启，反馈 dmesg（`Resume caused` 无记录 = 芯片 alarm 未触发）|
| mem 失败 | 立即重试 1-2 次（系统有 2s 内近期 alarm 时 mem 被拒属正常）|
| 测试期间时间对不上 | 设备 RTC 时间可能落后真实时间，属预期；测试期间不要手动改系统时间（拨时钟会让已设的 RTC_WAKEUP alarm 延后）|
