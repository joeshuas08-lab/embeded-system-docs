# 定时休眠唤醒测试手册（客户版）

## 准备（每台设备一次）

刷机后 adb 默认关闭：先在设备上开 USB 调试（设置 → 关于平板电脑 → 连点
"版本号"7 次 → 返回 → 系统 → 开发者选项 → USB 调试）。

```sh
adb root
adb install AlarmTest.apk
```

日历 provider 已从固件移除；静止节流（`location_enable_stationary_throttle=0`）
已由固件固化，无需设置 —— 开机约 10 分钟的 Doze 静止检测唤醒已随之消除。

## 测试（核心 3 步）

```sh
# 1. 设定 5 分钟定时唤醒
adb shell am broadcast -n com.myir.alarmtest/.AlarmSetReceiver \
  -a com.myir.alarmtest.SET --es delay 300

# 2. 下发休眠
adb shell "echo mem > /sys/power/state"

# 3. 观察：设备休眠约 5-6 分钟后自动唤醒
```

## 验收标准

| 项 | 通过 |
|----|------|
| 定时唤醒 | 睡满设定时长后自动醒，不早于设定时间（最多晚约 1 分钟）|
| 无睡死 | 不超过设定时间 +2 分钟醒 |
| 稳定性 | 连续 10 轮全部通过（每 3 轮重启一次）|
| 产品 app | 用产品自己的 app 设置/下发，唤醒回调正常 |

## 1 小时定时唤醒（充电，客户复现场景）

```sh
adb shell am broadcast -n com.myir.alarmtest/.AlarmSetReceiver \
  -a com.myir.alarmtest.SET --es delay 3600
adb shell "echo mem > /sys/power/state"
# 预期：休眠约 1 小时（中途不醒，包括跨越整点），之后自动唤醒
# 验证：
adb shell su 0 cat /data/data/com.myir.alarmtest/fired.txt   # 有新行 = alarm 触发
adb shell su 0 dmesg | grep "Resume caused"                  # IRQ 80, hym8563 = RTC alarm
```

## 异常时反馈

```sh
su 0 dmesg | grep -E "Resume caused"
```

附输出 + 现象描述。（另可附 `/data/data/com.myir.alarmtest/fired.txt` 判断 alarm 是否真触发）

注意：测试期间不要手动修改设备时间（拨时钟会让已设的定时唤醒延后）。
