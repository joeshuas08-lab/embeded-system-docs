# 休眠唤醒策略说明（两级方案）— MYD-LR3576 V6

日期：2026-10-13

## 背景

客户去掉 App 自己的定时功能后，设备休眠中仍会被系统周期唤醒。源码排查结论：这些唤醒
（JobScheduler deadline、DeviceIdle 维护窗口、蓝牙 metrics、WiFi health 等）全部经过同
一条硬件通路——alarmtimer → hym8563 的 RTC 中断 → GPIO0_C5 → 唤醒 SoC。属于 Android
平台的固有行为，不是某处故障。

按产品要求（休眠中只允许 App 的闹钟唤醒，按键/充电不受影响）做两级处理：

## 第一级：默认交付，客户基于此验证

commit `09a0e61f111` — alarm: only allowlisted packages may arm wakeup alarms

- AlarmManagerService 策略：非白名单包的 RTC_WAKEUP / ELAPSED_REALTIME_WAKEUP 闹钟
  在设置时降级为非唤醒型
- 非唤醒型闹钟走普通 CLOCK_BOOTTIME / CLOCK_REALTIME 定时器（JNI 映射表
  android_alarm_to_clockid 可查），休眠中不会触发，只在下次醒来时补投
- 白名单：`persist.sys.wakeup_allowlist`，默认 `com.cry.acoustic_pocket`；
  置空 = 关闭策略
- 按键 / 充电唤醒不走闹钟通道，不受影响

行为：休眠中只有 App 的闹钟能唤醒设备；系统服务的定时都推迟到下次醒来处理。

## 第二级：备选（第一级验证不通过时采用）

commit `cc7e8a02cb7` — rtc: forbid RTC IRQ from resuming the SoC (fallback)

- DTS 加 `myir,disable-alarm-wakeup;`，驱动 hym8563 用它把 RTC 中断移出唤醒路径
- 效果：完全禁止 RTC 定时唤醒（包括 App 的闹钟）；休眠中只能靠按键/充电唤醒，
  所有到期闹钟在醒来后补投
- 只动内核 + DTS，与第一级相差一个内核启动镜像

## 交付与验证流程

1. 默认交付 = 含第一级的整包（用 `09a0e61f111` 构建）
2. 客户基于第一级验证
3. 验证不通过 → 采用第二级：重编内核（当前 HEAD `cc7e8a02cb7`）出 boot.img，
   替换即可，系统侧不动
4. 回退方法：
   - 第一级：`setprop persist.sys.wakeup_allowlist ""`（空值关闭策略）
   - 第二级：删掉 DTS 里的 `myir,disable-alarm-wakeup` 重新编译内核
